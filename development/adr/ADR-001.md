# ADR-001  薄客户端架构（后端唯一权威态）

- 状态：已接受（2026-09-02 追认，Phase 4 落地）
- 关联：production-readiness-plan.md / lessons-learned.md

## 背景

Phase 4 前系统为纯前端内存引擎（flow.js 3739 行状态机 + 18 种子模块 + localStorage 持久化），业务逻辑在浏览器端，无法多端一致、无法真正鉴权。

## 决策

前端只做展示与交互（Vue 3）；后端（Spring Boot + MySQL）承担业务状态机、RBAC 单点校验、乐观锁、审计、定时任务；前端本地 db 为后端快照（/api/snapshot）的响应式镜像，写操作 POST 后端 + 写后重取（refreshDb 防抖 200ms）。

## 备选方案

备选：① 保留内存引擎 + 后端仅存储（数据一致性差、权限可绕过，否）；② 全量服务端渲染（演示交付成本高，否）。

## 后果

收益：数据一致性/权限不可绕过/多端一致；成本：前端读路径依赖快照水合（登录页不依赖 db），写后 200ms 防抖合并。
